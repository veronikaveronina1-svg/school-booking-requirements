# Нефункциональные требования и глоссарий

## Нефункциональные требования

| ID | Категория | Требование | Как проверить | Связанные истории |
|---|---|---|---|---|
| NFR-01 | Производительность | Уведомление преподавателю отправляется не позже чем через 1 минуту после сохранения пробного | Создать тестовую запись, замерить время до получения сообщения | US-03 |
| NFR-02 | Надёжность | Сбой отправки уведомления не приводит к потере записи о пробном | Имитировать недоступность мессенджера, проверить, что запись сохранена | US-01, US-03 |
| NFR-03 | Надёжность | При сбое уведомления менеджер видит предупреждение | Имитировать сбой, проверить наличие предупреждения | US-03 |
| NFR-04 | Безопасность | Доступ к карточкам детей ограничен ролями: менеджер и преподаватель видят только необходимые им данные | Войти под разными ролями, проверить доступные поля | Все |
| NFR-05 | Безопасность | В уведомлении преподавателю передаются только имя, возраст, группа, дата и время, без телефона родителя и других лишних данных | Проверить текст уведомления | US-03 |
| NFR-06 | Персональные данные | Обработка данных детей и родителей соответствует законодательству о персональных данных | Проверка юристом школы | Все |
| NFR-07 | Удобство | Менеджер создаёт пробное не более чем за 2 минуты (после обращения родителя, при готовых данных) | Замер времени на тестовых записях | US-01, US-02 |
| NFR-08 | Удобство | Преподаватель видит пометку «пробное» в списке группы с телефона | Открыть список группы на смартфоне | US-04 |
| NFR-09 | Аудит | В системе сохраняется история: кто и когда создал, изменил или отменил пробное | Создать и изменить запись, проверить журнал | US-01, US-06 |
| NFR-10 | Совместимость | Решение работает вместе с AlfaCRM и не требует её замены | Проверка архитектуры и документации системы | Все |

## Допущения и вопросы к уточнению
- Права доступа в AlfaCRM для разных ролей **неизвестны** (допущение: у менеджеров и преподавателей права разные). Требует уточнения у руководителя или администратора системы.
- Значения в требованиях (1 минута, 2 минуты) условные и согласовываются с заказчиком.
- Соответствие законодательству о персональных данных нужно подтвердить с юристом. В этом документе нормы не трактуются.
- Состав данных в уведомлении (NFR-05) ограничен намеренно: чем меньше данных уходит через мессенджер, тем ниже риск утечки.

## Глоссарий

| Термин | Определение |
|---|---|
| AlfaCRM | Система учёта клиентов, расписания и посещаемости, которую использует школа |
| CRM | Система управления взаимоотношениями с клиентами: хранит данные о клиентах и их обращениях |
| Пробное занятие | Бесплатное первое занятие, на котором ребёнок знакомится со школой до покупки |
| Абонемент | Оплаченный пакет занятий |
| Группа | Постоянный состав учеников, занимающихся вместе по расписанию |
| Карточка группы | Страница группы в AlfaCRM: расписание, состав, преподаватель |
| Карточка ребёнка | Страница ученика в AlfaCRM: данные, история посещений |
| Менеджер | Сотрудник школы, принимающий заявки и записывающий на пробное |
| Преподаватель | Сотрудник, проводящий занятия и отмечающий посещаемость |
| Посещаемость | Отметка о том, пришёл ли ребёнок на занятие |
| Конверсия | Доля клиентов, дошедших до следующего шага. Здесь: доля пробных, закончившихся покупкой абонемента |
| Стейкхолдер | Человек или группа, на которых влияет проект или которые влияют на него |
| AS-IS / TO-BE | Процесс «как сейчас» / процесс «как должно быть» |
| User Story | Требование в формате «Как <роль>, я хочу <действие>, чтобы <ценность>» |
| Критерии приёмки | Условия, по которым проверяют, что требование выполнено |
| Use Case | Пошаговое описание взаимодействия пользователя и системы для достижения цели |
| НФТ | Нефункциональное требование: описывает качество работы системы, а не её функции |
